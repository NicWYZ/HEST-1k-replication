RECONSTRUCTED FROM RAW OUTPUT. HEST's benchmark.py writes <exp_code>::<timestamp> directories
and exp_code was chosen per submission wave, so the same head appeared under several names
(faithful_pca_ridge, faithful_ridge, faithful_xgb, a14_xgb_raw, probe_xgb_nopca). Runs killed
at their wall limit were completed by a second job with a _part2 exp_code, leaving one
(head, encoder) split across two directories, and the interrupted parent additionally held a
PARTIAL task directory with no results_kfold.json. code/scripts/reorganize_repo.py resolved
this per (head, encoder, task): the directory that actually contains results_kfold.json wins,
newest timestamp breaking ties, partial task directories dropped. The redundant inner encoder
level was flattened. Configuration for each run is code/configs/<head>__<encoder>.yaml.

NOT PRESENT. dataset_results.{csv,json} were removed. They are per-RUN summaries, so for
hoptimus1 - executed as 10 single-task jobs to fit the GPU queue - each covered one task and
the surviving copy advertised a single-task average as the encoder's score. The authoritative
per-task table is results/summary/results_task.csv.

hoptimus1 was run as 10 separate single-task jobs; code/configs/pca_ridge__hoptimus1.yaml is
the equivalent single config.
