What is here: the round-3 task-definition files. One JSON per (task, label set):
ten <TASK>.json with label_set 'shipped' plus IDC_audited.json with label_set
'audited' (TENX95 and TENX99 merged into one donor). Every later round-3 stage reads
tasks through these files instead of hard-coding the benchmark's ten task names.
task_def_validation.csv carries one row per file with the counts and the pass/fail of
each assertion, and is written before the JSON files on every run.
